## 1. 背景与目标

### 1.1 现状

当前「方块花园」是**纯体素编辑器**：

- 世界数据是 `Uint8Array` 体素网格（`src/core/world.ts`，10×10×10）。
- 可摆放物只有两种：`BlockId` 单格方块（`src/core/block-types.ts`）、体素预设 `PRESETS`（`{dx,dy,dz,type}`，如 tree / bush / flowerBed，`src/core/presets.ts`）。
- 网格由 `buildVoxelMesh` 合成（`src/core/mesh-builder.ts`）。
- 渲染接口是纯体素的：`RendererAdapter.syncWorld(WorldSnapshot)` / `applyBlockDelta(BlockDelta)`（`src/rendering/renderer-api.ts`）。

**没有任何加载或渲染任意 3D 网格的能力。**

### 1.2 目标

引入一个**按单元格摆放的三维模型道具层**（方案 B，**不做体素化**）：

- **基础地块仍为方块**（体素层保留）。
- **道具是真实 3D 网格**（如 Kenney Platformer Kit 的低多边形模型：树、木箱、木桶、蘑菇、石头、栅栏、旗帜、金币、弹簧、平台等）。
- 道具**遵循按单元格摆放的规则**（占据整格坐标），但**不要求所有物体都是方块**。

### 1.3 非目标（本次）

- 不替换/移除现有体素预设（先保留，后续再评估迁移）。
- 不引入运行时模型解析（FBX/GLB/OBJ）、WASM、Worker。
- 不做动画/骨骼/物理；道具为静态网格。

## 2. 硬约束

来自容器与打包规范（`.skill/minitool-zip-builder`）：

| 约束 | 说明 |
|---|---|
| zip 文件类型 | 仅允许 `.html .css .js .json .png .jpg .jpeg .gif .webp .svg .woff .woff2`；**`.fbx/.glb/.obj/.mtl` 不允许进包** → 模型必须**离线转换**为内联 JS/JSON 几何，或以 `.png` 承载 |
| 运行时加载 | 禁止 `three/examples` 加载器（FBXLoader / GLTFLoader / OBJLoader 等）、禁止 WASM、禁止 Worker → **运行时零解析**，几何在构建期烘好 |
| 脚本形态 | 经典脚本，ES2017 / Chrome 61 基线，无 `import`/`export`、无 top-level await |
| 资源 | 全部打包在内，无任何外部域名引用 |
| 性能预算 | 每帧 ≤ 100 draw call、≤ 100k 三角形；纹理边长 ≤ 2048、显存 ≤ 64MiB；DPR ≤ 1.5 |
| 两适配器 | Three 与手写 WebGL 需保持一致；WebGL 兜底不投影阴影（沿用既有分工） |

> 素材：**Kenney Platformer Kit（License 已核实为 CC0，可商用）**。目录 `D:\Documents\lzx\assets\platformer-kit` 含 153 个独立模型（FBX/GLB/OBJ 各一份）+ 共享 `colormap.png`（各格式目录 `Textures/` 下）+ `Previews/`（153 张单模型预览 PNG，作图标源，§7.2）。
> 注意：**不存在** `platformer-kit.fbx` 这样的合并文件；需按单个模型选取；12 个候选模型名已逐一核实存在（§12）。

## 3. 总体架构

```
┌───────────────────────────────────────────────┐
│  app.ts  组装                                   │
├───────────────────────────────────────────────┤
│  core/                                          │
│    world.ts (体素)      prop-world.ts (道具)    │
│    mesh-builder.ts      prop-types.ts           │
│    history.ts (+道具动作)  presets.ts            │
│    voxel-raycast.ts (walkRay) + pick.ts (统一拾取) │
├───────────────────────────────────────────────┤
│  rendering/  renderer-api.ts (+道具接口)        │
│    adapters/three-adapter.ts  (+道具分批渲染)    │
│    adapters/webgl-adapter.ts  (+道具 program)    │
│    color-temperature.ts                          │
├───────────────────────────────────────────────┤
│  assets/  props.generated.ts (构建期产物)        │
└───────────────────────────────────────────────┘
```

要点：

- **体素层与道具层分离**：体素层继续用 `World`/`buildVoxelMesh`；道具层用独立的 `PropWorld`。
- **数据在 core，引擎无关**；两适配器只接收数据。
- **模型表（静态）与实例（运行时）分离**：模型几何一次上传，实例仅记录 `modelId + 格坐标`。
- **统一拾取**：DDA 底层抽成 `walkRay`，方块命中与道具命中共用同一步进/法线语义（§8.1），两适配器行为一致、无需 `Raycaster`。
- **共用批几何构建**：两适配器共用 `buildPropBatch`（core/prop-mesh-builder.ts）——同一份数据、同样的分批与变换规则（§6.2）。

## 4. 数据模型

### 4.1 模型表（构建期生成，静态）

```ts
// src/core/prop-types.ts
export interface PropModelData {
  readonly name: string;             // 展示名，如 "小树"
  readonly icon: string;             // 调色板图标（data:image/png;base64,...，源为 Previews，§7.2）
  readonly positions: Float32Array;  // 3/顶点，已按 scale 表归一化、底面落在格底
  readonly normals: Float32Array;    // 3/顶点
  readonly colors: Float32Array;     // 3/顶点（从 colormap 采样，sRGB）
  readonly indices: Uint16Array;     // 单模型索引（恒 < 65k 顶点）
  readonly footprint: number;        // 占地格数（整数，1 = 单格；平台类可为 2）
  readonly height: number;           // 占高格数（整数，≥ 1）
}
```

- `footprint/height` 不只是展示信息：**占用列**（`footprint × footprint × height` 的柱体格集合）是拾取与摆放规则的依据（§4.3、§8）。
- 单模型 `indices` 恒为 Uint16；**运行时合并成批几何时必须重建为 Uint32 索引**（§6）——几十个实例的合并顶点数即可超过 65,535。

### 4.2 实例（运行时）

```ts
export interface PropInstance {
  readonly id: number;           // PropWorld 内部自增分配
  readonly modelId: number;     // 模型表索引
  readonly x: number;           // 基础格坐标（整格；占用列自此格向上）
  readonly y: number;
  readonly z: number;
  readonly rot: 0 | 1 | 2 | 3;  // 绕竖直轴 90° 旋转（首版固定 0，字段保留）
}
```

### 4.3 道具世界（基础格 + 占用列双映射）

```ts
// src/core/prop-world.ts
export interface PropWorld {
  /** 基础格 → 实例 */
  readonly props: ReadonlyMap<number, PropInstance>; // key = cellKey(基础格)
  /** 放置：占用列与现有道具占用重叠即失败 */
  add(x: number, y: number, z: number, modelId: number): PropInstance | null;
  /** 从任一占用格移除整个道具（经占用映射回溯基础格） */
  removeAt(x: number, y: number, z: number): PropInstance | null;
  /** 占用查询：该格被某道具占用列覆盖则返回其实例 */
  propAt(x: number, y: number, z: number): PropInstance | undefined;
  clear(): void;
  list(): PropInstance[];
}
```

- `cellKey(x,y,z)` 用整数编码（如 `x + y*S + z*S*S`）。
- **占用列**：实例占用格集合 = 基础格向上 `height` 格、`footprint × footprint` 的柱体；内部维护两份映射（`基础格 → 实例`、`占用格 → 基础格`），`add / removeAt` 同步维护两份。
- `PropWorld` **不依赖体素世界**，只校验道具占用重叠；「占用列全部格在 `World` 中为 `AIR`」由调用方结合 `World` 校验（§8.2）。

## 5. 渲染接口扩展

`renderer-api.ts` 按「只新增可选方法」的冻结规则扩展（`RENDERER_API_VERSION` +1）：

```ts
export interface PropDelta {
  readonly added: ReadonlyArray<PropInstance>;
  readonly removed: ReadonlyArray<{ x: number; y: number; z: number; modelId: number }>;
}

export interface RendererAdapter {
  // ……既有方法……

  /** 一次性上传模型表（可选） */
  definePropModels?(models: readonly PropModelData[]): void;
  /** 全量：首次加载 / 撤销 / 清空 / 恢复存档 / 切换适配器（可选） */
  syncProps?(instances: readonly PropInstance[]): void;
  /** 增量：正常放置 / 删除（可选） */
  applyPropDelta?(delta: PropDelta): void;
}
```

- 采用可选方法，NullAdapter 无需实现（保持兜底兼容）。
- 光照/色温/曝光/阴影沿用 `setTheme` 与既有 uniform，无需新增。
- 分批（§6）是适配器内部实现，接口不感知批；`applyPropDelta` 增删实例自带 `modelId`，适配器据此只重建受影响批。

## 6. 适配器实现

### 6.1 Three 适配器

- **按 modelId 分批**：每个模型一个 `BufferGeometry`，批内合并该模型全部实例（按实例 `x,y,z + rot` 平移/旋转/缩放模型顶点，顶点色写入 `color` 属性）。体素层 1 批 + 道具 ≤12 批 ≈ 13 draw call（Three 阴影深度遍历另计，仍远低于 100 预算）。
- **批索引必须 Uint32**：单批合并顶点数轻松超过 65,535（如 100 棵树 ≈ 20 万+ 顶点），`setIndex(new THREE.BufferAttribute(new Uint32Array(...), 1))`；Three 在 WebGL1 下自动启用 `OES_element_index_uint`。
- 材质：`MeshLambertMaterial({ vertexColors: true })`（与体素网格一致的光照/色温/曝光，无图集贴图），`castShadow = receiveShadow = true`。
- 变更时**只重建受影响 modelId 的批**；`syncProps` / 撤销 / 切适配器时全量重建。单批顶点量远小于旧「整层单几何」方案，缓解整层重建的 GC 压力。
- 阴影：复用现有 `DirectionalLight.castShadow` 与阴影相机范围。

### 6.2 手写 WebGL 适配器

- 新增**第二个 program**：顶点色、无图集采样；顶点着色沿用现有 `uMatrix`，片元沿用现有光照公式（`uAmbient + (1-uAmbient)*diff`）、`uExposure`、`uLightTint`、`RECIPROCAL_PI`、`toSRGB`。
- **`setTheme` 须同时更新两套 program 的 `uExposure` / `uLightTint`**——现状只写 `this.program` 的 uniform，加了第二个 program 后若遗漏会造成两渲染器观感分叉。
- 几何上传：与体素一致，`gl.bufferData` 直接传 typed array，每帧重绑属性；**同样按 modelId 分批**（每模型一组 pos/nrm/col/idx buffer，≤12 批）。
- **索引宽度**：`drawElements` 用 `gl.UNSIGNED_INT`，初始化时 `gl.getExtension('OES_element_index_uint')`（Chrome 61 支持，属普遍可用扩展；缺失时 `init` 抛错、工厂按既有降级路径切到其余适配器——比分段绘制简单且诚实）。
- 无阴影（与既有约定一致）。
- 与 Three 共用同一份 `positions/normals/colors/indices` 与同样的分批规则，保证观感一致。

### 6.3 一致性验证

无头浏览器分别用 Three / WebGL 渲染同一场景，比对关键像素，纳入验证脚本。

## 7. 离线资源烘焙管线

**构建期脚本**（不进包，只在开发机运行）：`scripts/bake-props.mjs`，**纯 Node、零新增依赖**（GLB 与 PNG 均可直接解析，Node 内置 `zlib` 足够）。

### 7.1 几何解析（主案：纯 Node 解析 GLB；已核实真实文件结构）

- 输入：`Models/GLB format/<name>.glb`。GLB = 12 字节头 + JSON chunk + BIN chunk，直接解析 glTF accessor。**已核实全部候选模型为同一常规布局**：单 scene/单 node（无 TRS 变换）/单 mesh/单 primitive（mode 4），属性 `POSITION / NORMAL / TANGENT / TEXCOORD_0`，indices 为 `SCALAR`。
- 提取与守卫（fail fast，不静默出错）：
  - `POSITION / TEXCOORD_0` 须为 `FLOAT`（5126）；indices 须为 `UNSIGNED_BYTE`（5121）/ `UNSIGNED_SHORT`（5123）/ `UNSIGNED_INT`（5125）——**实测小模型用 5121**；node 带非恒等 TRS、sparse accessor、KHR 变换扩展带 offset/scale 时报错退出；
  - **按面拆解（de-index）+ 重算平面法线**：实测顶点跨面共享（tree 800 顶点 / 1224 索引）且 NORMAL 为平滑法线——Kenney 平色低模需要每面独立顶点；故**不采用 NORMAL accessor**，拆解为每面 3 顶点，法线取面叉积归一化，顶点色取面中心 UV 采样的单一平色。
- 归一化尺寸：**每模型一张 scale 覆盖表**（目标水平尺寸，格）——实测 Kenney 模型以 1 单位 ≈ 1 格为基准（tree ≈1.1×1.9×1.1、coin ≈0.4×0.4×0.4、platform ≈1×0.2×1）；脚本按包围盒缩放使水平最大边等于目标尺寸、底面落到格底；`footprint / height` 由缩放后包围盒**自动取整导出**（不手填，避免与视觉不符）。
- 顶点色：解码 `Textures/colormap.png`（**已核实 512×512、8 位 RGBA、非隔行**；Node 内置 `zlib` inflate + 自写 PNG 解滤器，处理 filters 0–4），**按面中心 UV 采样**（面中心取三顶点 UV 均值后取最近纹素，避免色块边界渗色）。
  - 注意：glTF 的 UV 以**左上角为原点**、v 轴向下，PNG 行序恰好自上而下——直接按 `(u, v)` 采样，**无需 flip**。

### 7.2 图标（直接用 kit 自带 Previews）

- `Previews/<name>.png` **已核实为 64×64 索引色 PNG（PLTE + tRNS，非隔行）**——无需解码、缩放与重编码：读文件、校验 PNG 签名与 IHDR 尺寸（64×64）后**直接 base64 原文件**，内联为 `data:image/png;base64,...`。
- 不需要构建期 3D 光栅化，也不需要 PNG 编码器；PNG 解码器仅用于 7.1 的 colormap 采样。

### 7.3 序列化与产物

- 输出 `src/assets/props.generated.ts`：`PropModelData[]`，几何以 **base64 二进制**内联（运行时 `atob` → `Uint8Array` → `Float32Array`/`Uint16Array` buffer 视图，只是数据解码、**不含任何模型格式解析**，「运行时零解析」表述成立）；文本十进制列为备选（更可读，体积约大 30%）。
- 体积估算：12 模型几何 + 图标 ≈ **300–400KB**（当前 `dist/app.js` 491KB / zip 129KB，加上后仍远低于 2MiB 单文件风险线与 10MiB 上限）。**以阶段 1 实测为准**。
- 产物只含我们自己的几何数据与 data URI 图标，不含 GLB/FBX/OBJ；`three/examples` 不进入任何依赖。

备选：本地 Chromium/Edge + three + GLTFLoader 跑一次加载——需要额外驱动机制（CDP / Playwright，均未在依赖内），仅在纯 Node 路线遇到解析障碍时启用。

## 8. 摆放规则（按单元格，统一拾取）

### 8.1 统一拾取（`src/core/pick.ts`）

- `voxel-raycast.ts` 抽出**逐步 DDA 底层 `walkRay`**（每步给出当前格与进入面法线）；既有 `voxelRaycast` 与新 `pick` 共用同一步进与法线语义。
- `pick(origin, direction, world, propWorld, maxDistance)`：DDA 每步**先查 `propWorld.propAt`（占用列），再查 `World` 方块**，返回首个命中：

```ts
interface PickHit {
  readonly kind: 'prop' | 'block';
  readonly x: number; readonly y: number; readonly z: number;   // 命中格
  readonly nx: number; readonly ny: number; readonly nz: number; // 进入面法线
  readonly prop?: PropInstance; // kind === 'prop' 时
}
```

- 「先到先得」天然消除旧稿「道具格优先于地形」的补丁规则：道具在前就先命中道具，地形在前就先命中地形；占用列使「点树冠删掉树后方地形块」不再发生（树冠格都在占用列内，先于后方地形命中）。

### 8.2 放置

- 目标格 = 命中格 + 法线（**命中 prop 或 block 一视同仁** → 叠放在道具之上自然成立：点树冠顶面，目标格 = 占用列上方第一格）。
- 校验（全部满足才放置）：
  1. 目标格及**整个占用列**均在 10³ 世界边界内；
  2. 占用列全部格在 `World` 中为 `AIR`（道具模型体积不得插入地形）；
  3. 占用列不与任何现有道具占用重叠（`PropWorld.add` 内部校验）。
- 吸附整格中心；道具底面坐落于所在格底部。

### 8.3 删除

- 按 `PickHit.kind` 分派：`prop` → 经占用映射回溯基础格、**整个道具移除**；`block` → 现有方块删除逻辑。

### 8.4 旋转

- 首版固定 `rot = 0`（字段与数据链路保留，后续启用只加按键与存档字段，另行迭代）。

### 11.2 阶段计划（每阶段可独立验证）

1. **烘焙脚本 + 生成资产**：确定模型集与 scale/footprint/height 表，产出 `props.generated.ts`，校验数据形状与**实测体积**（对齐 §7.3 估算）。
2. **core 道具世界 + 统一拾取 + 历史 + 存档 v2**：单测覆盖占用列、prop/block 命中优先级、放置/删除/撤销/迁移。
3. **接口 + Three 适配器（分批 + Uint32）**：无头截图确认落格、受光、色温、曝光正确；增量只重建受影响 modelId 的批。
4. **WebGL 适配器（第二 program + UNSIGNED_INT + 双 program 主题同步）+ 一致性**：像素级对比。
5. **UI 调色板 + 输入/放置/删除/撤销/存档接线**：无头验证「放置 → 撤销 → 重开恢复」。
6. **打包与审计**：产物禁用项扫描（无外部引用/无被禁 API/无 GLB 残留）、`audit_artifact.mjs`、输出到 `build/`。

## 12. 决策记录（原待确认事项，已定）

1. **模型集**：采纳建议组 12 个（已逐一核实存在）：`tree`、`crate`、`barrel`、`mushrooms`、`rocks`、`plant`、`fence-straight`、`sign`、`flag`、`coin-gold`、`spring`、`platform`。`character-oozi`（GLB 219KB，全 kit 最大单件）**不纳入首版**。
2. **旋转**：首版固定 `rot = 0`；字段与数据链路保留，后续启用只加按键与存档字段。
3. **占格规则**：升级为**占用列规则**（§4.3/§8）——单格占用与视觉体积的矛盾（点树冠误删后方地形、无法在道具上叠放、方块塞进树冠）由占用列 + 统一拾取一并解决。
4. **阴影**：沿用既有分工——Three 投射/接收阴影，WebGL 兜底不投影。
5. **图标**：直接用 kit 自带 `Previews/*.png` 缩放 64px 内联（§7.2），不用 emoji 占位。
6. **范围**：既有 tree/bush/flowerBed 体素预设**保留**，后续再评估迁移。

## 13. 风险与备注

- **架构级改动**：破坏「纯体素」抽象，需同时改造两个适配器与存档格式，工作量显著。
- **观感混搭**：平滑模型与方块同场景，风格可能不统一（可接受，取决于美术取向）。
- **性能**：模型三角形远多于方块；按 modelId 分 12 批（≈13 draw call）+ Uint32 索引控制；增量只重建受影响批，缓解整层重建的 GC 压力。
- **三角形预算守卫**：最坏情形（如 10×10 全摆树 ≈ 110k 三角）会破 ≤100k 预算——放置时按各模型 `indices.length / 3` 估算总量，**超 ~90k 拒放并 toast**。
- **运行时零解析**：几何全部构建期烘焙，产物中不含 FBX/GLB/OBJ；base64 → typed array 仅为数据解码，非模型解析。
- **烘焙脚本为一次性投入**：纯 Node 自写 GLB/PNG 解析（约数百行），无新依赖、可单测；换素材只需重跑脚本。
- **真机验证**：本编辑器结论不代表容器通过；最终仍需创服平台模拟器 + Android/iOS 真机验证。
